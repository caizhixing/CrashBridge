# Firebase adapter support boundary

**Real Firebase console compatibility has not been verified.** All fixtures are synthetic; these tests are not production acceptance evidence.

- Only HTTPS `console.firebase.google.com/project/<project>/crashlytics/app/android:<package>/issues/<issue>` is recognized. The corresponding App/list route supplies project/App context. Only `eventId` is retained; job hashes and unrelated queries are removed from IssueRef URLs.
- Lists use actual issue anchors inside `tr`, `[role="row"]`, or `li`. A row containing different issue identities is not selectable. Controls live in independent Shadow DOM and use namespaced markers; Firebase links, state buttons and other native controls are not clicked or replaced. Selected rows are sent to the persistent background queue, so users can continue on another page.
- Detail support is deliberately narrow: one `crashlytics-stack-trace`, `.stacktrace`, `.stack-trace`, `[aria-label="Stack trace"]`, or `[aria-label="Stacktrace"]` region; alternatively one section/region labelled by exactly one `Stack trace`/`Stacktrace` heading. Nested recognized regions are treated as one. More than one independent region or code block is unsupported, not guessed to belong to the same event.
- Stack content must contain a Java `at ...(...)` or Android native `#N pc ...` frame. Exception text without frames is `missing-stack`. Generic page text or unscoped `pre` is never used. The actual displayed cause-chain text is retained without synthesizing frames.
- Optional metadata uses unambiguous `dl` / `dt` / `dd` pairs only inside `crashlytics-event-details`, `.event-details`, or regions labelled `Event details` / `Issue statistics`:  App version, Version code/Build version, OS version/Android version, Device model, Events, Users, Time range, Event timestamp/Event time. Missing or duplicate fields are null. Localized or unknown labels are not guessed.
- Content waits for rendered DOM changes for at most 60 seconds and sends one result per UUID job. Known missing/unsupported layouts remain visible while waiting, then send that failure; the background alarm is the independent timeout fallback. A Google sign-in form fails immediately. If navigation leaves the Firebase content-script origin entirely, the background owns timeout/URL validation; this script cannot inspect the external login page.
- Only the currently displayed representative event is captured. Completeness is unknown, or partial when collapsed/busy content or truncation is detected. No claim is made about newest event, all threads, or all variants. No hidden content is expanded.
- No Cookie, private API, raw DOM export, remote script, or whole-page text is read. Selection does not change Firebase issue state. Capture warnings and the injected UI both disclose unverified compatibility.
- Node's built-in tests use a minimal DOM boundary fake with real adapter parsing and real domain validation. DOM/UI/Chrome glue coverage: **n/a**. No third-party DOM package or browser automation is involved.
